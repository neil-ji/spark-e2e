---
description: Scan frontend UI code to generate a style conventions file used by spark-e2e review. Use when setting up spark-e2e in a project, when the design system changes, or when UI review results are inconsistent.
argument-hint: "[project root directory]"
---

Generate or update `AESTHETICS.md` by scanning the frontend codebase for UI conventions.
This file is automatically injected into every `spark-e2e review` VLM prompt.

## Workflow

### Phase 1 — Discover Stack

Identify the frontend framework and tooling:

1. Check `package.json` for dependencies: React, Vue, Next.js, Nuxt, Svelte, Tailwind, etc.
2. Find the source directory (common patterns: `src/`, `app/`, `components/`, `pages/`).
3. Look for design-system config files (tailwind, theme, CSS vars).

### Phase 2 — Extract Conventions

Scan the codebase for **concrete, quantifiable** values. For each category:

#### Spacing
- Read Tailwind config (`tailwind.config.*`) → `theme.extend.spacing` or default scale.
- Scan component JSX/TSX for padding/margin/gap patterns: `p-{n}`, `m-{n}`, `gap-{n}`, `space-{n}`.
- Check global CSS for `--spacing-*` or similar CSS custom properties.
- Determine the **base spacing unit** (4px / 8px / 10px).
- Output: base unit, common padding values, section gaps.

#### Color Palette
- Read Tailwind config → `theme.extend.colors` or `theme.colors`.
- Read CSS custom properties: `--color-*`, `--c-*`, `--*-color` on `:root`.
- Read any theme/color JSON or TS files.
- Categorize colors by semantic role: primary, secondary, accent, success, warning, danger, neutral, background, text.
- Output: color name, hex value, and usage context.

#### Typography
- Read Tailwind config → `theme.extend.fontSize`, `theme.extend.fontFamily`.
- Scan component code for text size patterns: `text-{size}`, `font-{weight}`, `leading-{n}`.
- Check global CSS for `--font-*` vars, `@font-face` declarations, or imported fonts.
- Determine heading hierarchy (H1-H4 sizes) and body text size.
- Output: font families, size scale with line-heights, font weights used.

#### Layout & Grid
- Scan for grid/flex layout patterns across pages/layouts.
- Check responsive breakpoints (Tailwind defaults or custom).
- Check max-width containers, sidebar widths, content area widths.
- Output: breakpoints, container max-width, column counts, common sidebar widths.

#### Component Patterns
- Sample 5-10 key components (Card, Button, Input, Modal, Table, Nav, etc.).
- For each: extract dimensions (height, min/max width), padding, border-radius, shadow, border.
- Check for consistent patterns: "all cards use `rounded-xl p-6 shadow-sm`".
- Check form elements: input heights, label alignment, error state placement.
- Output: per-component spec with actual values found.

### Phase 3 — Generate AESTHETICS.md

Write `AESTHETICS.md` at the project root using this exact format:

```markdown
# UI Style Conventions
<!-- Generated by /style-init. Re-run after design-system changes. -->

## Spacing
<!-- Base unit and common spacings -->
- Base unit: {n}px (Tailwind scale: {description})
- Element padding: {list common padding values with usage}
- Section gap: {list common gap values with usage}
- Container padding: {value}

## Color Palette
<!-- Semantic colors and their hex values -->
- Primary: {name} `{hex}` — buttons, links, active states
- Secondary: {name} `{hex}` — secondary buttons, badges
- Accent: {name} `{hex}` — highlights, focus rings
- Success: {name} `{hex}` — confirmations, positive trends
- Warning: {name} `{hex}` — alerts, cautions
- Danger: {name} `{hex}` — errors, destructive actions
- Background: {name} `{hex}` — page background
- Surface: {name} `{hex}` — card/panel background
- Text primary: {name} `{hex}`
- Text secondary: {name} `{hex}`
- Border: {name} `{hex}`

## Typography
<!-- Font families and size scale -->
- Font: {primary font}, {fallback stack}
- Scale (with line-height):
  - H1: {size} / {line-height}, weight {weight}
  - H2: {size} / {line-height}, weight {weight}
  - H3: {size} / {line-height}, weight {weight}
  - Body: {size} / {line-height}, weight {weight}
  - Caption: {size} / {line-height}, weight {weight}

## Layout
<!-- Grid, breakpoints, containers -->
- Breakpoints: {list of breakpoints}
- Max content width: {value}
- Standard grid: {columns} columns, {gap} gap
- Sidebar width: {value} (if applicable)

## Component Specs
<!-- Key component dimensions and styles -->
### Card
- padding: {value}
- border-radius: {value}
- shadow: {value}
- min-height: {value} (if applicable)

### Button
- height: {value} (default), {value} (small)
- border-radius: {value}
- padding-x: {value}
- min-width: {value} (if applicable)
- font-weight: {value}

### Input / Form Field
- height: {value}
- border-radius: {value}
- border: {value}
- label alignment: {left|top}
- error placement: {below|inline|tooltip}

### {Other key components as discovered}
```

**Rules for filling values:**
- Use **actual values** found in code, never guess.
- If a value varies across the codebase, note the range: "16px–24px, most common 20px".
- If a pattern is NOT found, write "Not detected" instead of omitting.
- Keep the `{description}` placeholders brief and factual.
- Only add component sections for components that actually exist in the codebase.

### Phase 4 — Verify

1. Run `cat AESTHETICS.md` to confirm the file was written correctly.
2. Cross-check 2-3 values against the source code to ensure accuracy.
3. Report: how many components were sampled, which files were the primary sources.
